# File tree

Every source file, with one line on what it holds. A header marked `(.cpp)`
has its definitions in the matching path under `src/`. Keep this current:
adding, moving or deleting a file updates this tree in the same commit.

## `include/achilles/`

- `build_config.hpp.in`: generated by CMake. Constants saying which optional
  parts this build has.

## `include/util/`

- `buffer.hpp` `(.cpp)`: an aligned, owning byte buffer.
- `io.hpp`: console output helpers.
- `simd_ops.hpp`: helpers that treat scalars and SIMD batches alike: masks,
  lane counts, reductions.
- `tmp.hpp`: type-list metaprogramming: concat, repeat, unique, transform,
  apply, index-of.
- `yaml.hpp`: YAML reading helpers.
- `gl/gl.hpp` `(.cpp)`: a minimal OpenGL 3.3 core function loader.
- `gl/gpu.hpp` `(gpu_egl.cpp, gpu_none.cpp)`: the headless GPU context
  camera sensors render through; the `none` build throws.
- `gl/mesh.hpp` `(.cpp)`: an instanced, lit triangle mesh on the GPU.
- `gl/shader.hpp` `(.cpp)`: a compiled and linked GL program.

## `include/domain/`

- `joint_data.hpp`: per-joint addressing and data as loaded: `JointAddress`,
  `JointRef`, `JointField`, `JointAttachment`.
- `joint_layout.hpp`: maps each joint to its sorted row and back.
- `joint_topology.hpp`: each row's parent, plus segmented and pair
  topologies.
- `sim_clock.hpp`: the sim's one clock: time reached and ticks taken.

### `math/`

- `scalar.hpp`: one value per instance, as a field type.
- `vector3.hpp`, `vector6.hpp`: 3- and 6-vectors.
- `matrix.hpp`: fixed-size matrices and blocks.
- `quaternion.hpp`: unit quaternions, with `Exp` and `Log`.
- `activation_mask.hpp`: per-lane bit masks.

### `random/`

- `counter_rng.hpp`: a counter-based generator; each draw depends only on
  stream, counter and index.
- `seed.hpp`: a seed from the system's random source.

### `spatial/`

- `transform.hpp`: rigid transforms, with `Exp` and `Log`.
- `dual.hpp`: spatial vectors: velocity, acceleration, momentum, force.
- `inertia.hpp`: rigid-body and articulated inertia.

### `geometry/`

- `segment.hpp`, `rectangle.hpp`, `box.hpp`: branch-free shape queries.
- `ray.hpp`: a ray and its hit, for range sensors.
- `swept_box.hpp`: the sphere-swept box every body collides as.
- `visual_shape.hpp`: the shape a body is drawn as.
- `unit_meshes.hpp`: unit shapes as triangles, for drawing.

### `error/`

- `effects.hpp`: the error-model building blocks: scale, bias, random walk,
  noise, saturation, quantization.

### `archetype/`

- `archetype.hpp`: one archetype as read from the user.
- `archetype_set.hpp`: every archetype together: name lookups and instance
  numbering.

### `attachment/`

- `attachment.hpp`: what sensors and actuators share: options, readings,
  ticks and the `Attachment` base.
- `attachment_config.hpp`: an attachment's `.arow` settings, read by name.
- `attachment_kind.hpp`: what a kind must declare to be one.
- `sim_quantities.hpp`: the sim quantities kinds and state handles can
  reach.

### `sensing/`

- `sensor.hpp`: the base every sensor kind is written in.
- `encoder.hpp`, `gyroscope.hpp`, `accelerometer.hpp`, `magnetometer.hpp`,
  `lidar.hpp`, `camera.hpp`: the modelled sensor kinds.
- `truth_sensor.hpp`: exact sensors, one per sim quantity.

### `actuation/`

- `actuator.hpp`: the base every actuator kind is written in.
- `dc_motor.hpp`: a DC motor and its driver.
- `truth_actuator.hpp`: exact force and torque actuators.

## `include/engine/`

- `assembler.hpp`: converts domain types to and from flat scalar leaves.
- `field_contract.hpp`: what a well-formed field enum is.
- `op_contract.hpp`: what an op must declare: `ArgData`, `ArgIndex`,
  `OpLike`.
- `algorithm_contract.hpp`: `StepLike`, `Algorithm` and `AlgorithmLike`.

### `memory/`

- `arena.hpp` `(.cpp)`: the one fixed, bump-allocated block.
- `binding.hpp`: reads each field's traits: sharing, ordering, indexing,
  layout, buffering.
- `buffering_policy.hpp`: single and double buffering.
- `sim_allocator.hpp`: builds the arena and the SimContext from the
  archetypes at init.

### `topology/`

- `layout_policy.hpp`: planar and segmented field layouts.
- `indexing_policy.hpp`: per-row, per-lane-group and global indexing.
- `orderings.hpp` `(.cpp)`: the ordering policies: linear, topological,
  list, pair.
- `ordering_plan.hpp`: an ordering's init-time row placement.
- `group_mask_filter.hpp`: which pairs a collision group and mask allow.

### `view/`

- `view_contract.hpp`: what a view and its cursors must provide.
- `view.hpp`: an algorithm's typed access to its fields.
- `view_factory.hpp`: builds a view type from an algorithm's traits.

### `pass/`

- `row_policies.hpp`: the pieces traversals are built from: sources,
  ranges, scans.
- `traversals.hpp`: row, tree, linear, segment and pair traversals.
- `op_invoker.hpp`: calls an op with the field values a traversal points at.
- `algorithm_step.hpp`: runs a list of passes in order.
- `sim_context.hpp`: holds every view and topology, and runs step lists.
- `view_step.hpp`: an optional base for steps that run over a whole view.
- `repeat_while_step.hpp`: repeats a step list while a whole-sim flag is
  set, up to a cap.

## `include/algorithms/`

- `conventions.hpp`: the concrete types and lane count.
- `shared_slots.hpp`: the shared-slot tags.
- `physics_algorithms.hpp`: the hosting list of physics algorithms.
- `registry.hpp`: the full hosting list: physics, then attachments.
- `integrators.hpp`: the tick lists, the setup list and integrator
  selection.
- `sim_config.hpp`: whole-sim config: base transform, velocity and
  acceleration.
- `orderings/collision_pairs.hpp`: the collision pair row set.
- `attachment_kinds/attachment_kinds.hpp`: the registered sensor and
  actuator kinds.
- `attachment_kinds/sim_input.hpp`: binds each sim quantity to the field
  that holds it.

### Algorithms

Each has `<name>_data.hpp`, `<name>_ops.hpp` `(.cpp)` and
`<name>_step.hpp`, unless noted.

- `aba/`: articulated-body dynamics: joint accelerations from state and
  torque. Also swaps the actuator torque buffer.
- `vi/`: velocity integration.
- `pi/`: position integration on SE(3).
- `verlet/`: velocity Verlet stages.
- `midpoint/`: implicit midpoint stages.
- `rk4/`: Runge-Kutta 4 stages.
- `broad_phase/`: collision bounds and candidate pairs.
- `narrow_phase/`: contacts between candidate pairs.
- `joint_limit/`: joint limit rows.
- `contact_solver/`: the soft-constraint contact solver (MuJoCo-style CG).
- `attachment/`: runs every sensor and actuator kind. Ops are header-only.
- `clock/`: advances the sim clock at the end of each tick. Data and step
  only.

## `include/interface/`

- `simulation.hpp`: the `Simulation` object: load, init, step, and handle
  lookups.
- `archetype_loader.hpp` `(.cpp)`: loads `.arow` files into archetypes.
- `sim_config_loader.hpp` `(.cpp)`: loads `sim_config.yaml`.
- `attachments.hpp`: configures every declared sensor and actuator at init.
- `attachment_handle.hpp`: the handle for one sensor or actuator.
- `state_handle.hpp`: an unsynchronized handle to one sim quantity at one
  joint, for debugging and logging.
- `state_quantities.hpp`: which quantities state handles reach, and which
  they can write.
- `writable_handle.hpp`: the one write interface shared by writable state
  handles and actuator handles.

## `include/display/`

Sensor displays and controllers that steer the sim, outside it.

## `src/`

Mirrors `include/`; see the `(.cpp)` marks above.

## `tests/`

- `<path>_<file>.cpp`: one test per header, named after its path
  ([testing.md](conventions/testing.md)).
- `examples_<name>.cpp`: one test per example, plus one per shared example
  helper.
- `consumer/`: builds Achilles as a library from another project.

### `support/`

- `toy_field.hpp`: a minimal two-field algorithm for engine tests.
- `toy_buffered_field.hpp`: a minimal double-buffered algorithm.
- `toy_reduce_field.hpp`: a minimal algorithm with a global field.
- `mask_archetype.hpp`: the concept archetype for `MaskLike`.
- `simd_test_helpers.hpp`: builds batches lane by lane.
- `registered_sim.hpp`: every hosted algorithm, built from real `.arow`.
- `aba_reference.hpp`: hand-derived ABA reference cases.
- `joint_row.hpp`: the row a joint lives at in ABA's views.
- `sensing_scene.hpp`: hand-written scenes for sensor tests.
- `shaft_scene.hpp`: a one-body shaft scene for actuator tests.
- `temp_dir.hpp`: a scratch directory removed on destruction.

## `examples/`

- `<name>/`: one example each: its scene, sim config and program
  ([examples.md](conventions/examples.md)).
- `viewer/`: runs any scene in real time and opens a window per sensor.
- `shared/robots/`, `shared/sensors/`, `shared/actuators/`: `.arow` files
  shared across examples.
- `shared/real_time.hpp`: the real-time loop example programs share.
- `shared/flying_camera.hpp`: a camera window flown by hand.

## `scripts/`

- `check-format.sh`, `check-tidy.sh`, `check-tidy-analyzer.sh`: format,
  lint and static analysis checks.
- `check-conventions.py`: checks the rules in `docs/conventions/` that a
  script can check exactly.
- `run-<name>.sh`: builds and runs one example.
- `validate-long-horizon.sh`: long ABA validation against the closed-form
  double pendulum.

## Other

- `.devcontainer/`: the dev container.
- `.github/workflows/`: CI, and the CI image build.
- `.githooks/pre-commit`: blocks commits that aren't clang-format clean.
